# Changelog

All notable changes to CrossRev. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed

- **Preflight no longer rejects a GitHub App installation token as unauthenticated** ([#17](https://github.com/carlosboeing/crossrev/issues/17)). It proved `gh` was usable by reading `GET /user`, which an installation token cannot reach — the token is scoped to the installation, not to a user, so a working credential came back 403 and the leg died at its first step. Automated mode authenticates as an App installation on every run, so this failed **every automated run in every repository**, and the offline suite never saw it because a laptop holds a user token where `GET /user` succeeds. Each kind of token is now asked for its identity at the endpoint that suits it — `user` for a user token, `installation/repositories` for an App installation — and `rate_limit`, which every token type can reach, settles anything that answers neither. Only reaching none of the three counts as unauthenticated. The failure message split too: on a runner it names the `app-token` the workflow passes, because `gh auth login` is not something a runner can do and there was never anything wrong with the credential's shape.

- **Preflight checks that a tool runs, not just that it exists** ([#18](https://github.com/carlosboeing/crossrev/issues/18)). `_tool_version` probed everything with `--version` and folded stderr into what it captured, so a tool that rejected the flag had its complaint read as its version — under a tick. OpenSSL is the one that shows it: its own subcommand is `openssl version`, and the build on GitHub's hosted runners refuses the flag, so runs printed `✓ openssl Invalid command '--version'`. openssl is now probed with its own subcommand, and **a tool that returns nothing version-shaped fails the check** rather than passing it. That second half is the substance: as written, the check passed for anything that merely existed, which is the opposite of what the comment above it says it is for — a broken openssl would have sailed through and died later inside credential decoding or JWT signing, a long way from the cause. Missing and present-but-not-answering are reported apart, because installing it again is the one thing that will not fix the second.

- **`crossrev auth status` revalidates the App's identity instead of reporting a cache** ([#5](https://github.com/carlosboeing/crossrev/issues/5)). `auth login` records an App's name and slug once, at registration. Renaming the App in its settings moves both, and nothing local noticed — so the one command whose job is answering "is my credential set up correctly" answered confidently from a file that could be wrong. It now signs the JWT it was already minting for the installations check, reads `GET /app`, and reports what came back. **The cached copy is corrected in place when it has drifted**, which is a write from a status command and deliberate: the cached slug is not decoration. `state_trusted_author` falls back to it when `CROSSREV_APP_SLUG` is unset, so a stale slug makes an automated run started from a machine trust an author that does not exist — no markers read, pass 1 for ever, nothing reconciled. Detecting that and leaving it in place would have reported a fault it had already diagnosed, with hand-editing JSON as the only repair. Generated workflows were never exposed, because they pass the slug from the token step's `app-slug` output. An unreachable `GET /app` corrects nothing and claims nothing.

## [0.2.0] — 2026-08-16

A second way in, and a release process. CrossRev installs from npm without a clone, versions are now cut deliberately rather than per merge, and two display-level defects are fixed. **Automated mode is still built and unproven** — nothing here changes that, and proving it remains the `v1.0.0` bar.

### Added

- **CrossRev installs from npm, as `crossrev-ai`** ([ADR 0011](docs/adrs/0011-npm-as-a-second-install-route.md)). `npx crossrev-ai --pr 42` runs the local loop without cloning anything, and `npm install -g crossrev-ai` is a second way onto your PATH. **The installed command is still `crossrev`** — only the package identifier carries the suffix, because npm refuses `crossrev` as too similar to the long-established `cross-env` and that check has no appeal. Homebrew, GitHub Releases and the repository itself are unaffected and keep the plain name. The package is the same bash the clone runs, with no build step and no dependencies — Node is needed to install it and for nothing after that. macOS and Linux only, declared in the manifest so Windows fails at install rather than at first run. **`crossrev init` still needs a clone**, because it pins the composite action to a SHA read from CrossRev's own git checkout and an npm package has none; it stops with an error naming the cause rather than writing a workflow pinned to nothing. Publishing runs on a tag through trusted publishing, so no npm token exists in this repository or on a laptop.
- **The linter fails when the version drifts.** `package.json` and the `VERSION` file both carry the version, because npm reads one and `crossrev --version` reads the other. `scripts/lint.sh` now compares them, and the release workflow compares the tag against both. The failure it prevents is quiet: a published package whose own `--version` disagrees with the registry it came from.
- **A release process, written down and partly enforced** ([ADR 0012](docs/adrs/0012-versions-are-cut-deliberately.md)). Versions are cut deliberately rather than per merge, so changes accumulate here until one is. `scripts/check-changelog.sh` fails a pull request that changes what ships without recording it, reading the shipped set from `npm pack` so it cannot drift from the `files` allowlist — which means docs, tests and CI changes are exempt without anyone maintaining a list of exemptions. `scripts/next-version.sh` reports the bump the Conventional Commit types since the last version tag already imply, rather than deciding it a second time from a diff. Major is reported and never chosen, because `v1.0.0` is gated on proving automated mode rather than on a commit type.

### Fixed

- **Generated GitHub App display names take the product name** ([#4](https://github.com/carlosboeing/crossrev/issues/4)). `crossrev auth login` named the Apps it creates `crossrev-<owner>` and `crossrev-refresh-<owner>` — lowercase, in the one place the product is named outside a terminal, sitting in an organisation's installed Apps list beside `Claude` and `Vercel`. They are now `CrossRev <owner>` and `CrossRev Refresh <owner>`, per [ADR 0010](docs/adrs/0010-name-crossrev.md). **The slug is unchanged**, because GitHub derives it by lowercasing and turning spaces into hyphens — which matters, since `state_trusted_author` matches that slug literally and a change would make automated mode trust an author that does not exist. A new `tests/test-auth.sh` asserts both halves so the name and the slug cannot drift apart. Existing Apps are unaffected; renaming one is a single field in its settings.

- **The pass label moves instead of accumulating** ([#2](https://github.com/carlosboeing/crossrev/issues/2)). Each pass added `crossrev/pass-N` without taking the previous one off, so a three-pass pull request carried three grey pills and the reader had to scan for the highest. The pass label is mutually exclusive like the four state labels beside it, and is now treated that way. Which labels to take off is read from the pull request rather than counted down from the cap, so a new revision that resets the counter to 1 sheds the higher labels a finished cycle left behind. A display defect rather than a state one — the markers were always correct and `crossrev status` was never affected.

## [0.1.0] — 2026-08-13

The first release, and the one that made CrossRev its own thing. Everything below ships for the first time — there are no earlier released versions, because the tool spent its whole life so far inside another repository under a working title.

**Automated mode is built and unproven.** No repository has had the generated workflows installed, so no real event has ever chained one leg to the next. That is what `0.x` records, and proving it is the `v1.0.0` bar. Local mode has run against real pull requests.

### The extraction

- **Extracted into `carlosboeing/crossrev`, a public repository of its own**, with its real 71-commit history rather than one squashed commit. A private `carlosboeing/crossrev-workbench` sidecar holds the build-process working memory; this repository holds the code, the user docs and the decision record.
- **Renamed from the working title `revloop` to CrossRev.** `Revloop` is a commercial product shipping since 2022, and in B2B software "rev" reads as revenue before review. `CrossRev` names the differentiator instead, and encodes no reviewer count so a multi-reviewer roadmap survives it. One ordered case-sensitive sweep across about 1,340 occurrences in 55 files plus six filenames, with the offline suite unchanged before and after. Reasoning in [ADR 0010](docs/adrs/0010-name-crossrev.md).
- **Delivery is now a composite action pinned by full 40-character SHA**, with the tag as a trailing comment. Consuming workflows reach it with `uses:` and no credential.
- **The source-checkout delivery mode is retired**, and more went with it than the checkout: the read-only SSH deploy key, its `CROSSREV_SOURCE_KEY` secret, the origin-URL parse that discovered the source repository, and three workspace exclusions whose only job was hiding the extra checkout from `git add`, from a temp-index capture, and from a changed-paths walk. A composite action runs outside the consumer's workspace, so all three were dead the moment delivery changed. **An automated setup now needs two secrets rather than three.** [ADR 0009](docs/adrs/0009-delivery-via-sha-pinned-composite-action.md).
- **The credential refresher keeps a checkout, deliberately**, because `crossrev auth refresh` is not expressible through the action's `leg` input. It is a plain public checkout — no token, no key, no secret — and it still never checks out the pull request branch, runs a model, or reads a diff.
- **A `trigger` action input**, defaulting to `automatic`. The automatic-versus-human distinction controls the policy caps and the draft skip, and collapsing the leg to `uses:` left the old shell branch nowhere to live. It defaults the opposite way to the CLI on purpose: forgetting it in a workflow should give you the caps, not an uncapped loop.
- **The composite action runs a dependency preflight as its first step.** Nothing in any template had ever installed `jq`, `yq`, `gh` or `openssl` — it was implicitly "the runner happens to have them". A consumer's workflow cannot forget a check that lives in the action.
- **Ten ADRs, a seven-page documentation set, and a public roadmap.** Distilled from the private design record rather than copied, so each one stands alone.
- **The public documentation states plainly that `git pull` in the checkout is the update and deleting it is the uninstall.** There is no `crossrev update` command yet, and pretending otherwise is the failure mode.

### Added

- **Tests for `bootstrap.sh` and `install.sh`** — the two scripts a stranger runs first, and neither had one. Sixteen assertions covering `find_checkout`'s three branches and the skills hand-off contract.
- `openssl` added to the preflight's core dependency list, which had never named it despite the credential path decoding a restored token with it.
- **A two-direction template/default drift test.** Eleven behavior leaves must agree after the explicit setup exemptions are removed, so a contradictory default fails and a template key the code no longer implements fails too.

- `crossrev review --pr N` — one review pass. Claims before working, posts one inline comment per finding on the line it affects, records everything in a hidden marker on its own summary comment, and hands the loop to the resolve leg by label.
- `crossrev resolve --pr N` — verifies every finding whatever its severity, commits and pushes what it fixed, replies in-thread, resolves what it settled, and persists deferred defects to a sink before resolving their threads.
- `crossrev cycle --pr N` — the whole loop in one process, up to `max_passes_per_cycle`, and what a bare `crossrev --pr N` runs. A thin driver over the same legs the workflows invoke, because state lives on the pull request rather than in process memory.
- `crossrev status --pr N` — position *and* interruption, naming the command that resumes a leg that died mid-flight and saying whether a re-run would resume it or abandon it as stale.
- `crossrev init` — the upgrade to automated mode, behind an itemised plan naming every path, secret and label, where deferred work will go and where that answer came from, and anything it would overwrite. `--dry-run`, `--yes` and `--upgrade`.
- `crossrev watchdog` — finds pull requests stuck waiting on a leg, retries once by re-firing the label, then halts and comments why. Re-applying a label GitHub already holds fires no event, so the retry removes it first.
- `lib/github.sh` — the whole GitHub boundary in one file: inline comments, threaded replies, GraphQL thread resolution, labels, issues, both dedupe tiers, the commit and the push. One file because that is what makes it stubbable.
- `lib/validate.sh` — structural checks in jq on what a harness returned. Deliberately not general JSON Schema validation, which bash cannot do.
- `lib/prompt.sh` — what each leg is given. Reproduces the skill text into the prompt rather than relying on harness discovery, because the quarantine moves the discovery paths out of the checkout.
- **Runner-aware `init`.** Which harnesses are reachable in CI is a property of the runner, so `init` refuses a pairing its runner cannot serve — naming the credential's measured lifetime and both fixes — instead of installing workflows that fail at the first API call. The generated workflows differ by runner: a hosted one installs the harness per run and receives credentials as secrets, a self-hosted one does neither.
- **`crossrev-token-refresh.yml` and `crossrev auth refresh`** — the single writer. Using a refresh token consumes it, so one scheduled job on its own concurrency group refreshes Codex's credential and every leg only reads. The vendor's token endpoint and client id are read out of the stored credential's own claims and its issuer's OpenID discovery document, never hardcoded: the endpoint is not where the obvious guess puts it.
- **Legs restore read-only.** A restored credential lands in a throwaway home that is discarded when the leg finishes, on the fatal paths as well as the clean one, so a harness that refreshes and writes back writes somewhere nothing reads again. A leg holding under an hour of token life stops and names both ways out rather than refreshing in flight.
- **`crossrev auth login --role refresher`** — a second App per owner carrying `Secrets: write` and nothing else, through the existing manifest flow. `init` derives whether a pairing needs one and never asks; a configuration that does not need it never hears of it and no key is created. Keys are now stored per owner *and* role at `<owner>.<role>.pem`, with the pre-role `<owner>.pem` still read as the loop's.
- **`init` captures `claude setup-token`** rather than asking for a paste, redacting anything token-shaped on its way to the terminal, and records the creation date — the only moment that information exists, since the token cannot be read back. `crossrev auth status` warns as the year closes.
- **`crossrev auth rotate`** — guided rather than absent. GitHub has no API for generating an App key, so this opens the right page, picks the downloaded `.pem` out of `~/Downloads`, proves it authenticates as that App, and only then replaces the old one.
- `lib/adapters/agy.sh` — Antigravity as a third harness. It constrains its own output natively, so it is schema-native alongside claude and codex; the amendment that asked for it expected a fenced-JSON fallback and was wrong.
- `lib/credentials.sh` — reading a token's expiry, issuer and client id from its own claims, restoring one read-only, and the refusal threshold.
- `templates/` — the workflows, the starter policy config, and a commented example operator config.
- `scripts/lint.sh` — syntax plus `shellcheck -S warning` across everything, in one command.
- A stubbed-`gh` test suite: 835 offline assertions across twenty files, no network, no model, no pull request. `tests/stub/codex` is a tripwire rather than a stub, because a fixture whose config failed to load reached the real billed CLI once before it existed. `tests/stub/agy` is a tripwire of a different kind: it exits non-zero if a flag follows `--print`, which is the mis-parse the real CLI answers cheerfully in prose.
- `action.yml` — the composite action consuming repositories call, pinned by full-length SHA. Its `app-token` input has no default on purpose: `GITHUB_TOKEN` writes do not trigger workflows, so defaulting it would stall the chain after pass 1 while looking healthy.
- `bin/crossrev` entrypoint with `doctor`, `version` and `help`.
- **`bootstrap.sh`** — the fetched script, so a machine with nothing gets to a working CLI in one command. It finds an existing checkout before cloning another — run from inside one, reachable by following an installed symlink back to its source, or already at the destination — then hands straight to `install.sh`, which keeps owning the requirements check, the PATH entry and the skills offer. `--dir`, `--ref`, `--repo`, `--yes`, and `--skills` / `--no-skills` passed through. The repository is public, so `raw.githubusercontent` serves it to a plain `curl` with no token, no `gh` and no credential of any kind.
- `install.sh` **offers the skills instead of printing a command to copy**, handing over to the `skills` CLI so that CLI asks its own questions — which harnesses, project or global, symlink or copy. `--yes` means "do not ask whether to install them", which is a narrower permission than answering three questions on someone's behalf; only the scripted path passes `--global --yes` through.

### Changed

- **`max_prs_per_day` now counts distinct pull requests repository-wide.** A review-and-resolve cycle counts once, repeated passes on the current pull request add nothing, and only trusted non-declined review markers inside the rolling 24-hour window participate. The repository issue-comments read stops at the threshold, caps itself at ten pages and announces any undercount.

- **Deferred work now has one `backlog:` contract.** `destination` selects GitHub issues, a repository path, nothing or automatic discovery; destination settings live under their own names, repository layout is explicit, and `crossrev config backlog` prints the resolved answer. Automatic discovery recognizes `BACKLOG.md`, stops treating `docs/ROADMAP.md` as a backlog, and writes the resolved layout into generated configuration.
- **Explicit false booleans are preserved.** Disabling missing-label creation, matched-issue comments or automation hints no longer falls through an accessor that treats `false` like a missing value.

- **The policy vocabulary now names its scope and unit.** `mode` is `local` or `automated`, autonomy settings live under `policy:`, and `max_passes_per_cycle`, `max_files_changed_per_pr`, `max_prs_per_day` and `min_fix_severity` replace the scattered caps and resolver threshold. `config.sh` is the single owner of the `github-hosted` runner default.
- **The missing-label guidance now matches the API.** Adding a label to a pull request creates one that does not exist with default metadata; only an API failure or an explicit existing-label-only policy blocks the operation.

- **Automatic review triggers are explicit and bounded.** Pull-request events pass `--trigger automatic`; a person invoking the CLI or posting `/crossrev review` gets one attended pass. `crossrev cycle` marks only the passes it generates as continuations, so it stops at `max_passes_per_cycle` without blocking a separately requested review. Automatic runs skip drafts and no longer fire on every push. The comment workflow now rejects authors outside OWNER, MEMBER and COLLABORATOR before a runner starts.
- **The second leg is `resolve`, not `address`.** The CLI verb, the label, the leg name inside every marker, the config section, the workflow file, the schema and the skill all move together. `address` parses as a noun before it parses as a verb, and `crossrev/awaiting-address` on a shipping or checkout codebase reads as a street address — a label that has to be explained has failed at the only job a label has. `resolve` also matches GitHub's own vocabulary, since this leg is the one that calls `resolveReviewThread`.
- **`crossrev run` is `crossrev cycle`, and a bare `crossrev --pr N` runs it.** `run` says nothing; every CLI has one. A **cycle** contains **passes**, and a pass has two **legs** — three words, each meaning one thing. The parse rule is written down rather than discovered: a first argument beginning with `-` is the default cycle, anything else is a subcommand, and an unknown subcommand is an error. So `crossrev reviw --pr 3` dies naming the typo instead of silently running the most expensive operation the tool offers, and bare `crossrev` prints help.
- **A finding's severity splits into three fields.** `severity` is now `high` / `medium` / `low`, `category` is a closed enum of `correctness`, `security`, `performance`, `maintainability`, `testing` and `docs`, and `pre_existing` is a boolean. One field was answering three unrelated questions — how bad is it, what kind is it, and did this pull request cause it — which is why a critical pre-existing security hole and a trivial pre-existing typo used to carry the same value and neither was ever fixed. Findings render as `[High · Security] Title`, with `· pre-existing` where it applies, and the summary table gains a category column. The `title` field itself is untouched, because a finding's stable id derives from it.
- **`addresser.skip_nits_after_pass` is `resolver.fix_at`.** One threshold — `high`, `medium` or `low` — naming the lowest severity a model may change code for while nobody is watching. Everything below it is still reported, still tabled, and still replied to; it is left for a human. The default is `medium`, which matches where Cursor Bugbot and OpenAI Codex sit. The verdict follows the same threshold: a pass converges when nothing at or above `fix_at`, and not pre-existing, remains. A separate reporting threshold was deliberately not added — it would make crossrev's own "this is an empty review rather than a filtered one" untrue. A value outside those three is refused when the config loads, because an unrecognised threshold otherwise ranks zero, counts nothing as actionable, and makes `fix_at: medum` look exactly like a clean review.
- **Pre-existing findings are never fixed here, whatever their severity, and that is not configurable.** It is the one guardrail worth hardcoding: a repository that lets the resolve leg fix pre-existing defects gets a pull request nobody can review.

Nothing above changes what CrossRev does. It changes what CrossRev calls things, and it gives the operator one dial where there was a hardcoded rule. Taken as one breaking change now because three of the four write into state that lives on the pull request — marker leg names, labels, and the severity words in every posted comment — so it is a find-and-replace today and a per-pull-request migration once the workflows are installed anywhere.

### Fixed

- **`bootstrap.sh`'s path arithmetic was wrong in five places**, because the tool is the repository root now rather than a subdirectory. Two of the five failed *silently* — they returned a real directory that was not the checkout, so the error surfaced later at the exec guard blaming the wrong thing. All of them now go through one `_is_checkout` predicate that requires both `install.sh` and `bin/crossrev`, so "is this a checkout?" is asked one way rather than four.
- **`install.sh` printed a skills command with `--skill` filters that could only go stale.** Root `skills/` holds exactly `pr-review` and `pr-resolve`, so the filters select everything. The hand-off is now `npx skills@latest add "$HERE"`, and the hint aimed at someone with no checkout names the public repository.
- **Every file-mode check reported the wrong answer on Linux.** The idiom was `stat -f '%Lp' … || stat -c '%a' …` — BSD first, GNU as the fallback. But `-f` on GNU `stat` is not an unknown flag: it means *file system status*, so it succeeds, prints `File: "…"`, and the fallback never fires. The consequence was worse than a wrong number: `crossrev auth status` warned that a correctly-moded private key was insecure and told you to `chmod` it, and a successful `crossrev auth login` reported its own freshly-written key as the wrong mode. Reversed at all three sites — `-c` is genuinely not a BSD flag, so it fails cleanly and the fallback fires on macOS. Found by this repository's first CI run, which is also the first time the suite had ever run on Linux.
- **`crossrev status` called a running leg a failure.** An unfinished leg got a red cross and "claimed 2 minute(s) ago, never finished" whatever was actually happening, while the pull request three inches away said the resolve leg was working — one state, two renderings, and the wrong one was in the terminal. The old line reasoned from the marker, which genuinely cannot tell a leg killed after forty seconds from one working for forty seconds, and then made a liveness claim anyway in the negative direction. The marker is not the only thing status can read: a local run records its pid and host in the lock file beside the git dir, and an automated one carries its `GITHUB_RUN_ID`, so `kill -0` and `gh run view` answer what the marker cannot. Four rows now, and only one of them is a failure — `◐ running now — started 7 minute(s) ago` where the process answers, `started 7 minute(s) ago on <host>` where the lock names a machine this one cannot test, `started 7 minute(s) ago, no result yet` where there is nothing to check and the window has not run out, and `✗ … abandoned` where the process is gone, the workflow ended without it, or the claim is past its window or against a revision that has moved. Evidence outranks the age in both directions: a workflow the API reports `completed` is abandoned two minutes in rather than an hour later, and a pid that answers is running at ninety minutes however stale its claim. The local pid is only tested where the lock file agrees that this pid, on this host, holds this pull request — a bare probe from another machine, or from the same one an hour later, can find a stranger's process and print exactly the false reassurance the old rendering was written to avoid. `NEXT` follows the rows: the leg's command keeps its place, because it is what resumes the pass if that run dies, but a leg that is running is told to wait rather than invited to start a second one over the same pull request.

- **"claimed" is gone from what CrossRev prints.** A leg posts its marker before it works so a second runner does not duplicate the pass, which is a claim in the code and a lease in the design — and neither is a distinction a person reading a status line has to make. The word is "started" wherever the output is aimed at an operator: the unfinished-leg rows, the warning that abandons a pass past its window, and the stale reason that used to say a claim "claimed" a revision. It stays in the code and the comments, where it is the precise word for what the marker does.

- **A path git could not write plainly was invisible to the anchor check.** The parser read paths as whitespace fields off the `diff --git` header, and that header carries two paths with no separator that cannot also appear inside a name — so `a/my file.md b/my file.md` became `a/my` and `file.md`. Anything outside printable ASCII is C-quoted instead, making the field a quoted, escaped string rather than a path. Either way the file matched nothing, so a finding on it could be neither validated nor snapped and fell straight back to a top-level comment — the failure the layer exists to prevent, on exactly the files least likely to be noticed. Paths now come off the `---` and `+++` lines, which carry one each and which any file with hunks always has, with git's C-quoting decoded because GitHub anchors on the raw path, under `LC_ALL=C` so an octal escape rebuilds one byte rather than one wide character. Finding it surfaced a second instance of the same class: the wanted path arrived through `awk -v`, which runs its value through awk's own escape processing, so a path containing a backslash was decoded on the way in and matched the wrong file. It arrives through the environment now.

- **The diff was read separately from the revision the comments were posted against.** `gh_pr_diff` asked for `repos/{repo}/pulls/{n}`, which returns whatever the diff is at the moment of the call, while `head_sha` came from the `gh pr view` the leg had already made. Two reads of a moving target: a push landing between them would have the anchor check validating line numbers from one revision and the comment posted against another. The fetch is now `compare/{base}...{head}` using the pair that single view call returned, so the two cannot disagree. Three-dot, so it diffs from the merge base exactly as the pull request view does — checked against pull request 14, where both endpoints returned byte-identical output.

- **A finding one line outside a hunk lost its thread, and the run said nothing.** GitHub takes a comment only on a line the diff shows, and the reviewer had to work its line numbers out by counting under a `@@` header — so on pull request 14 a finding landed on `CHANGELOG.md:14` when the sentence it faulted was line 13, the last line of the hunk. The comment fell back to the top of the pull request, which left no review thread, which sent the resolve leg's reply to the top of the pull request as well: one miscounted number, two orphaned comments. Three changes, each load-bearing on its own. The diff both legs read now carries a gutter giving every hunk line its old and its new number, so the number is copied rather than derived, and a dash marks the side a line cannot be commented on. The orchestrator re-checks each finding against that same diff before posting and moves one that missed onto the nearest line the diff does show, within three lines — the width of git's context, and so the margin a miscount lands in. Past that the reviewer meant somewhere else and the comment would be anchored to code the finding never mentions, so it falls back instead. The check runs before the finding's id is derived, because the id hashes a window of lines around the anchor and a line corrected afterwards would read as a different finding to the next pass.

- **The review leg reported a clean inline post over a degraded one.** `gh_review_comment_create` returns which of the two happened and the caller sent that answer to `/dev/null`, so a pass that anchored none of its comments read exactly like one that anchored all of them — the same defect fixed for the resolve leg's replies under "a reply that could not be threaded is no longer silent", which never reached this path. The count is now warned in the run's output and recorded in the summary comment, which also says the reply will land at the top of the pull request too. It survives a recovery the same way the reply count does: read back from the pass's own finding markers, since an anchored finding's marker is on a review comment and a fallback's is on an issue comment, so where the marker landed is already the record of which happened.

- **The backlog path was a regular expression, and it was operator input.** When the backlog destination is a path inside the repository, that path is dropped from the diff both legs read, so a leg does not review the file its own findings are written to. The path went straight into an ERE, which failed three ways at once. A dot matched any character, so `BACKLOG.md` also hid `BACKLOGxmd`. There was no end anchor, so it hid `BACKLOG.md.old` too, and a configured directory hid every sibling sharing its name as a prefix. And a filename carrying an unbalanced bracket — `docs/backlog(new).md` — was not a wide pattern but an invalid one: awk exited, `gh_pr_diff` emitted nothing, and the leg reviewed an empty diff and found nothing wrong with it. Files vanishing from a review is the one failure a review tool cannot report, because the output of a review that saw nothing looks like the output of a review that found nothing. Paths are now compared literally, as an exact file or a directory a path sits inside, and `gh_pr_diff` takes a list of them rather than a pattern.

- **And the same matcher could not read a path git wrote plainly.** It took the path as whitespace fields off the `diff --git` header, which is the defect fixed in the anchor parser one landing earlier and never applied here — so `a/docs/my notes.md b/docs/my notes.md` yielded `a/docs/my`, matched nothing, and the backlog file was reviewed after all. Exclusion now runs through `diff_exclude` in `lib/diff.sh`, beside the parser that already reads paths off the `---` and `+++` lines with git's C-quoting decoded. One implementation of that rule rather than two, which is what stopped the two from drifting the first time.

- **The count above that warning still called every comment inline.** The line reporting what the review leg posted was incremented once per finding whatever `gh_review_comment_create` reported, so a degraded pass printed a green `posted 5 inline comment(s)` directly above the warning saying some of them were not inline — the terminal half of the entry above, missed when the summary comment was fixed. It counts findings written out now, and the warning underneath is what splits anchored from fallen back. Subtracting the unanchored count would have been wrong on the resume path: that counter is seeded from the pass's own markers before the loop runs, so a run coming back after an interruption starts non-zero over findings it skips as already posted, and the difference can reach zero on a pass where inline comments genuinely landed.

- **A cycle interrupted inside the last allowed pass could not be resumed.** The pass bound stops another pass from starting, but `crossrev cycle` applied it before looking at the pass already under way — so a run killed between the review and resolve legs of pass 3 of 3 restarted, read the pass number, and exited clean with that pass's findings unresolved and its threads open. A halt that reads as a clean finish is the failure shape the loop exists to avoid. At the bound the cycle now finishes what it started: an unfinished review claim is resumed, an owed resolve leg runs, and then it stops without starting a pass.

- **And the resume was itself refused once the pass was numbered above the bound.** The half above resumed the claim as a continuation, which is what puts `max_passes_per_cycle` back in force — fine at pass 3 of 3, where the check asks whether a fourth may begin and 3 is not above 3, and wrong the moment the pass is 4. Pass 4 of a bound of 3 is a state an operator can legitimately be in, because `crossrev review --pr N` typed by hand runs one attended pass past the bound by design. Interrupt that pass, run `crossrev cycle`, and the resume met the bound it was numbered above: a declined marker written over a pass that was mid-flight, `crossrev/halted` applied, and a clean exit with the review unfinished. It did not recover on the next attempt either, because the declined marker then shadowed the claim it was written over. Whether the bound applies is now read off the marker rather than assumed: a `started` marker is an open claim, and the review leg resumes an open claim at its existing number, so the bound has nothing to bound. Any other unfinished state leaves the leg computing a pass number of its own, and there the continuation flag stays — dropping it outright would let a cycle start a pass above the bound, which is the one thing this whole branch exists to prevent.

- **A pass bound of zero switched the automatic loop off in one place and on for ever in another.** Zero is the orchestrator's own sentinel for "no pass bound applies to this invocation", which is what lets a person ask for one attended pass past the bound. An operator writing `max_passes_per_cycle: 0` or a negative number landed on that sentinel from the other direction, and the two readers disagreed: an automatic review skipped the pass check entirely and kept starting passes, while a cycle compared the pass number and stopped before the first one. The daily bound covers none of it, because repeated passes on one pull request cost it nothing. The value is now refused when the config loads, naming the key, on every path that reads it.

- **The default file backlog claimed to file a finding it had written nowhere.** `layout: file` with no path resolves to `.crossrev/backlog.md`, and `.crossrev` does not exist in a repository that has never run the loop. The append failed on the missing directory without stopping the function, which printed the path regardless — so the finding counted as filed and its thread resolved against a file nobody had written, which is the one failure persisting before resolving exists to prevent. The parent is created first, and a write that fails now returns non-zero instead of a path. The folder layout was never exposed to it, because it creates its directory before writing.
- **`crossrev status` said a review the reader asked for would be refused.** At `max_passes_per_cycle` it told them to raise the bound before running `crossrev review --pr N` — but the bound stops the loop continuing itself, not a person asking, so that command runs a pass either way. NEXT now says the loop will not start another pass on its own, names the key that changes that, and still ends in the command that works.

- **`crossrev status` recommended the address leg after the loop had converged.** It asked whether that leg had *run*, never whether one was *owed* — and a converged review is the reason the loop stopped, so none was. Following the advice would have run a pass over an empty findings list. Both that recommendation and the per-leg line now come off the review's verdict: `converged` and `blocked` owe no address leg, and the line reads "not needed" rather than "has not run", which describes work outstanding. Found by running the loop to convergence on a real pull request rather than by reading.
- **A file sink's deferrals were written after the commit, so they were committed by nothing.** The write goes into the working tree, so on an ephemeral runner it died with the container — while its thread resolved, because `tracked` was non-empty. The per-finding loop is now two passes with the commit between them: persist everything, commit, then reply and resolve. The sink write rides in the same commit as the fixes, and persist-before-resolve still holds. Reordering also exposed a second half: the commit was guarded on `fixed_count > 0`, so a pass that deferred everything and fixed nothing skipped it entirely and lost the write anyway. That guard now fires on a file-sink write too, with a commit message that says what it is for. The issue sink was never affected — it writes to GitHub, not the tree.
- **The addresser is now told which paths are not in the checkout.** The quarantine moves `CLAUDE.md`, `AGENTS.md`, `.claude/` and their siblings out before any harness runs, but the diff still carries their changes — so the reviewer raises findings there that the addresser cannot read, verify or fix. It would write to the absent path, the restore would delete the write, and the reply would report **Fixed**. Both the prompt and `skills/pr-address/SKILL.md` now name the exact list, require `deferred` rather than `fixed`, and forbid claiming a verification that cannot be performed. Excluding those paths from review instead was considered and rejected: a second model flagging a hostile instruction-file change is the point of the loop, and only the addresser is blind — the reviewer reads the diff.
- **`crossrev run` always died at the address leg.** `leg_review` takes the per-PR lock and nothing releases it — only the EXIT trap clears it — so `leg_address` in the same process found a live PID holding the lock and read it as a competing run. The lock is now re-entrant for its own process, held across both legs rather than dropped between them, because releasing mid-loop would let a second terminal start a pass halfway through this one.
- **The address leg posted no replies and resolved the threads anyway.** `state_posted_finding_ids` read the `id` out of every finding marker and discarded the `leg` the marker carries, but "already written out" means different things to the two legs: inline comments for one, replies for the other. The review leg stamps a marker on every inline comment, so the address leg found every id already present, skipped each reply as a duplicate, and resolved regardless — leaving a collaborator a resolved thread with no explanation in it. The leg is now a required argument.
- **A harness that is installed but has no adapter died on `command not found`.** `run_resolve_leg` returned as soon as the binary was on PATH, so naming `kimi` — a CLI plenty of machines have — dispatched `adapter_kimi` three steps later with nothing pointing back at the configuration that asked for it. The fallback had been taught not to *choose* such a harness; it could not help when one was named outright. Now refused up front, naming the endpoint route Kimi actually takes. `tests/stub/kimi` is a tripwire that fails loudly if the dispatch is ever reached.
- **The address leg committed crossrev's own source into the pull request.** `git add -A` walks `$GITHUB_WORKSPACE`, which is where the workflows put the `.crossrev-src` checkout, and git stages an embedded repository as a gitlink with a warning rather than an error. The quieter half: with `.crossrev-src` always staged, `git diff --cached --quiet` was never true, so the "reported fixes but changed no files" guard could not fire at all.
- **The `/crossrev review` comment trigger could never fire.** The fork check was ANDed in front of the whole job condition, and an `issue_comment` payload carries no `github.event.pull_request` — so that read was null, the comparison false, and both the `on: issue_comment` block and the comment branch were dead. The check now sits inside the `pull_request` branch. A comment cannot be fork-checked from its payload at all, so that moved into the first step of the job, before any checkout: an `issue_comment` runs in the base repository's context *with secrets*, and the next step checks out `refs/pull/N/head`. A guard that fired only once crossrev was running would already have put fork code on disk beside a subscription token.
- **A write to a quarantined path is no longer discarded in silence.** The restore moves `CLAUDE.md`, `AGENTS.md`, `.claude/` and friends back over whatever sits there, which is correct — letting a pull request's own instructions survive the quarantine is what the quarantine exists to stop — but a finding "fixed" by writing to one of those was reported as fixed, landed in no commit, and left the changed-nothing guard quiet because other files had changed. The clobbered paths are now named with their consequence.
- **The refresher swallowed the vendor's reason for rejecting a refresh.** Every diagnostic inside `cred_refresh_codex` went to stdout, which is where the function's return value goes, so each one was captured into the caller's `new="$(…)"` and thrown away with it. `token_expired` and `invalid_client` need different fixes and the difference is only in that body.
- **A tracker URL was treated as a repository-relative path.** `https://linear.app/acme/team/ENG` missed the GitHub-issues arm and matched the slash arm, so deferred work was written to a directory of that name inside the checkout — relative, so the inside-the-repo guard waved it through. A URL is now read the same way a bare `Linear` is: somewhere real, nothing to write to.
- **`crossrev/watchdog-retried` was never cleared**, making the watchdog's retry per-pull-request rather than per-stall. A pull request that stalled on pass 1, recovered, then stalled on pass 3 was halted on the spot for having already been retried, and someone had to remove the label by hand. A completed pass now clears it.
- **A `Tracker` field carrying a parenthetical gloss stopped meaning what it said.** Sink discovery matched the Project Map value against a bare `none`, but the convention's own example reads `none (ROADMAP.md is the single source of truth for "what's next")`. The gloss made the match fail, so the declaration fell through to the sniff and deferred findings were routed into `docs/ROADMAP.md` — a destination the repository had just declared it did not have. The gloss is now dropped before matching, which fixes glossed paths in the same move. Found by running `crossrev config sink` in this repository, where the offline test passed because it asserted the bare form.
- `install.sh` printed a skills command that finds nothing: the `skills` CLI does not walk into `tools/crossrev/skills/` from the repository root, and `--skill` takes one name per flag rather than a comma-separated list.
- The claude adapter never ran the CLI at all when no endpoint was configured — the default local case. An empty bash array expanded with a default yields one *empty* word, so `"${prefix[@]:-}" env … claude` ran the command named `""` and failed with "command not found" and an empty error string.
- Marker reads passed `--arg` to `gh api --jq`, which takes a bare expression: the jq program became literally `--arg`. It only ever worked by falling through to a second, correct call.
- `git ls-remote` failing was read as "nobody else pushed", so the check for a concurrent push to the branch silently did nothing on an unreachable remote. It now says the check did not run.
- Adapter stderr was discarded, so a fatal error inside an adapter — an endpoint that resolves nowhere, for instance — exited the process with nothing printed.
- The single-harness fallback could resolve a leg to `kimi`, which has no adapter behind it: Kimi is reached through the claude adapter as a named endpoint. The leg then died on `adapter_kimi: command not found` rather than on the missing harness it was actually short of. `crossrev doctor` reported the same three names for the same reason.
- `crossrev auth install` — runs the install half on its own, for the closed tab or the new repository a year later.
- A one-shot local listener on the redirect, so the browser lands on a real page and the terminal carries on by itself. `nc -k` keeps the socket open across connections: serving one connection and re-binding was measured losing the redirect whenever anything else connected first, because the re-bind gap returns connection-refused.
- Installation verification — `auth login` opens the install page with the account prefilled, then signs an RS256 JWT with the stored key and polls until GitHub confirms the installation. "Registered" no longer reports success for an App that can reach no repository.
- `crossrev auth login` — registers a GitHub App through the [App Manifest flow](https://docs.github.com/en/apps/sharing-github-apps/registering-a-github-app-from-a-manifest), prefilling the three permissions and disabling the webhook so the form offers nothing to get wrong.
- `crossrev auth status` — which Apps are configured, for which owners, and whether each private key is still mode 0600.
- `install.sh` — symlinks `bin/crossrev` onto PATH and reports what's missing. Skills are left to the `skills` CLI.
- `lib/ui.sh` — the six output rules from the design, enforced by the helper signatures rather than remembered per call site. `ui_warn` and `ui_die` both require a second argument, so a warning always states its consequence and an error always states the next action.
- `lib/preflight.sh` — dependency checks that name what's missing and how to install it, normalised to one `<tool> <version>` format across seven CLIs that each report themselves differently.

### Security

- **The refresher App's private key is never an organisation secret**, and never `--visibility all`. That key can rewrite repository secrets, and org-wide visibility would hand it to every workflow in the organisation — including crossrev's own review job, which checks out a pull request branch and runs a model over a diff. The whole argument for a second App is that its permission is unreachable from untrusted text.
- **Each adapter strips every credential that is not its own.** The workflow hands one process every credential the pairing might need; the agent process is the one reading attacker-controlled text, and a token it never receives is one no injection can talk it into exfiltrating. Codex's raw credential is stripped too, since by then it lives in `CODEX_HOME`.
- **The single-writer guarantee is repository-scoped, and says so.** Concurrency groups do not span repositories, so one credential belongs to one repository. `init` warns on an organisation-level copy, because the repository secret takes precedence — the repository you just set up works while every other one reading the organisation copy breaks.

### Migrating from the pre-extraction tool

There is exactly one operator, so there is no compatibility shim and none is planned — nothing was ever published under the old name. For that operator:

- **Rename the config directory:** `~/.config/revloop` becomes `~/.config/crossrev`. Copy rather than move, run `crossrev doctor` to confirm it reads the new location, and only then remove the old one. A bare `mv` onto an existing destination nests the old directory inside the new one instead of failing, which puts the App keys one level deeper than anything looks for them.
- **Delete the old clone at `~/.local/share/revloop`.** It is a checkout of the repository CrossRev was extracted from, which is exactly why it no longer qualifies as the tool. Deleting it is the old uninstall. Confirm what it is with `git -C ~/.local/share/revloop remote get-url origin` before removing it.
- **Reinstall from the public bootstrap**, which clones to `~/.local/share/crossrev` and symlinks `crossrev` onto your PATH.

No repository has the generated workflows installed, so there is nothing to migrate on the CI side and no pull request carries a marker under the old label namespace.
