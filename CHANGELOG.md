# Changelog

All notable changes to CrossRev. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Generated files are recognised without configuration.** CrossRev detects lockfiles, bundle names, minified files (`.md`, `.markdown`, `.mdx`, `.rst`, `.adoc` and `.txt` excepted), and generated headers using pure built-in rules seeded from Linguist's `generated.rb`, with base-revision `.gitattributes` (`linguist-generated`) as the repository authority. Fitting generated files are reviewed; oversized generated files are skipped with visible warnings in the pull request comment and terminal. The resolve leg keeps that warning, the policy exclusion line and the coverage footnote when it rewrites the review comment, quoting a header marker from the committed blob. Skips do not consume the 400 review slots, so later files can be reviewed and passes can converge. Excluded and skipped files are filtered from the resolve leg diff unless anchored by an open finding. A pull request with nothing left to review halts with `blocked` and `crossrev/halted` without invoking a model. The coverage engine advances to `file-v2`. See [ADR 0023](docs/adrs/0023-generated-files-are-recognised-without-configuration.md).

## [0.9.0] — 2026-09-26

### Fixed

- **The checkout token is no longer persisted in the checkout, and the legs remove a persisted one before they run.** The generated review, resolve and watchdog workflows now check out with `persist-credentials: false`, so the token is not kept in the checkout's git config for the rest of the job. The review and resolve legs also remove persisted `http.*.extraheader` values in the checkout's own form before the harness starts — only `AUTHORIZATION:` values, from the local config on the checkout v5 layout and from the separate credential file on the v6 layout — which covers checkouts from workflows generated before this change. The resolve leg's own fetch and push authenticate per invocation through `gh`. The composite action no longer interpolates the App token into its step script, which the runner writes to disk for the whole step; it tests `GH_TOKEN` from the step environment instead. Two consequences to know when upgrading: later steps in the same job lose the persisted credential too, so a custom step after the CrossRev step that runs an authenticated `git fetch` or `git push` needs its own authentication; and on a GitHub Enterprise Server host the resolve leg's git credential is gone with no replacement — the scrub removes the persisted token and the `gh` helper answers only github.com — so an automated resolve leg's push there has no credential.

- **The Claude Code review leg runs with an explicit read-only tool list and loads no operator MCP servers.** The reading leg passed no mode and no tool flags at all, so the session ran with whatever the operator's own settings carried. It now passes `--tools Read,Grep,Glob`, `--disallowedTools Agent,Skill` and `--strict-mcp-config`: the three read tools the review needs, with the Agent and Skill tools removed and no MCP servers at all (`--tools` covers built-in tools only and leaves MCP tools alone, so the flags travel together). The named-endpoint path builds through the same adapter and gets the same list. The resolve leg is unchanged — it needs its edit tools and keeps its argv.

- **An opencode install outside 1.x is refused before a leg starts.** opencode 2.x does not accept the flags the adapter passes and does not read the isolation config it writes ([#272](https://github.com/carlosboeing/crossrev/issues/272)), so a run on it would start without the constraints the config exists to hold. Both legs probe `opencode --version` first — outside the checkout, before the resolve leg's quarantine — and refuse any install that is not 1.x, and one whose probe reports no version, naming the supported range and the install to use rather than starting a leg that cannot run as intended.

### Added

- **`crossrev doctor` reports each installed harness's version against the versions on record.** The record is the descriptor's install pins — Claude Code 2.1.237-2.1.281 with recorded runs above the pin, Codex 0.148.0, Grok 1.0.5, opencode 1.18.21 — and nothing wider, so a pin bump moves the record with it. A version outside it reports as unverified rather than judged, and agy has no recorded range and says so. An install an adapter refuses — opencode 2.x today ([#272](https://github.com/carlosboeing/crossrev/issues/272)) — is reported in the adapter's own words and not counted as a harness, because no leg will start it.

## [0.8.0] — 2026-09-21

### Fixed

- **Ledger ref updates no longer fail against the GitHub API.** PATCH /git/refs takes a boolean force, and the `-f force=true` form field sent the string, so every update 422d. Each pass publishes at least twice to its slot ref — the initial generation, then each accepted batch — so the second publication always fell back to the marker while the ref held the initial generation. The update now sends a JSON body, and the offline `gh` stub holds GitHub's boolean rule.

- **The review and resolve skills forbid backslash escapes outside code spans.** A resolver once double-escaped its summary newlines, so a resolve summary posted literal `\n` sequences; the same flake could emit `\t`, `\r` or `\"`. Both skills now say plain characters; [#267](https://github.com/carlosboeing/crossrev/issues/267) tracks enforcing it deterministically.

- **A new review pass continues the ledger chain, reads never rewind it, marker digests cover the redacted bytes, and denied writes fall back.** A pass admitted after a completed one rooted an unrelated chain at generation 1, orphaning every earlier pass from the slot ref's ancestry; it now seeds from the slot's latest checkpoint for ancestry and numbering while verdicts still retire at a new revision. A generation read force-updated an existing ref to the handle being read, so reading an older generation rewound a concurrently advanced ledger; restores are create-only now. The marker store digested the pre-redaction bytes while the comment writer redacted the payload afterwards, so a credential-shaped string persisted a generation that never verified; both stores filter before encoding. Under `auto`, a denied blob, tree or commit write halted the pass instead of falling back, because only the ref-update error was classified as a refusal; permission and policy denials across the whole sequence report the typed refusal now, while transient failures still fail loudly.

- **Status and settle judge a pass by the producer it ran with.** The review leg records the resolved settings on its generations, but status and the resolve settle compared against the configuration text — so a pass that ran under a `--harness` override or a binary substitution converged and then failed the coverage obligation everywhere else. Both readers now take the producer off the pass marker, falling back to the configured reviewer for markers that predate the claim fields.

### Changed

- **CrossRev describes what it writes to a repository, and `doctor` reports the coverage ledger.** [What CrossRev writes](docs/what-crossrev-writes.md) carries the blast-radius contract as a contract — never outside its configured namespace, never under `refs/heads/` or `refs/tags/`, never deleting, never force-pushing a branch, never touching another slot's refs — each promise naming the code that keeps it, with the snippets for excluding the namespace from CI ref-fetching and mirrors, the mirror-push caveat, and the measured cost: 26 of the testbed's 30 advertised refs are already `refs/pull/*`, so one ledger ref per pull request roughly doubles a cost every repository carries. [ADR 0022](docs/adrs/0022-the-coverage-ledger-lives-in-git-refs.md) records the decision. `crossrev doctor` gains a coverage section naming the store in force and why, the namespace, the overflow behaviour, the resolved reviewer, and what the token can do — with the probe's limit stated plainly: it proves the permission, not the namespace. Evidence notes carry locations and reasoning, never source text, enforced by the shape validator refusing a note with a fenced block.

## [0.7.3] — 2026-09-17

### Fixed

- **A pass that enumerates no reviewable file can never report green, and a pull request that changes no files is settled without a reviewer.** A branch whose head matches its base — reverted, or overtaken by a merge, rebase or cherry-pick that brought the same work into the base — enumerates no required file. The review leg read that as "no coverage engine available" and fell through to the frozen single-prompt path, where `loaded.Scope` stays nil and both coverage gates in publication are keyed on it being set. Every convergence rule added in 0.7.0 was therefore skipped, and the model's answer alone decided the label: a model replying `converged` to a prompt with nothing in it put `crossrev/converged` on a pull request nothing had read. `policy.Converged` has always refused a required count of zero, and the frozen oracle pins it; nothing asked. A successful enumeration now binds the pass to its coverage obligation whatever it counted, so a green verdict on an empty set is downgraded rather than believed. Where git and GitHub agree the pull request changes no files, the leg settles the pass itself — blocked, with a reason CrossRev writes rather than a model, `crossrev/halted` applied, and no harness invoked; the observed run spent 20,327 tokens discovering there was nothing to read. Where they disagree, which a lagging API count after a force-push or a revert produces, the pass still runs, because the diff comes from the forge rather than from git and may hold real content — it can report findings, and it cannot report green. The summary names the comparison rather than a commit, because a revert, a merge and a rebase all reach this state and telling them apart would be a guess. It also no longer says a push restarts the loop: the generated review workflow subscribes to `opened`, `ready_for_review` and `labeled`, never to `synchronize`, so the next pass is started by a `/crossrev review` comment or the `crossrev/awaiting-review` label. Observed halting on `carlosboeing/crossrev-testbed#24` at v0.7.2, which is the same defect landing on its safe side by chance.

## [0.7.2] — 2026-09-17

### Fixed

- **Coverage ledger comments render one identifying line.** Every published shard and manifest comment was marker bytes alone, so a pull request collected a row of identical blank boxes showing GitHub's "No description provided." Each comment now opens with its generation, shard position and record count; readers scan for the marker delimiters, so leading prose changes nothing on the wire.

## [0.7.1] — 2026-09-17

### Fixed

- **Pinned actions run their own release again.** The composite action resolved its binary through `github.action_ref`, which arrives empty, so the empty ref fell through to the tag branch and every consumer silently downloaded the latest release whatever the pin said — v0.6.2 pins ran the v0.7.0 binary the hour it published. The action now reads the release from the `VERSION` beside itself, refuses an unversioned checkout, and logs the resolved tag.

## [0.7.0] — 2026-09-17

### Added

- **Review Intelligence lists every changed file.** One NUL-safe diff lists every added, modified, deleted, renamed and type-changed path. A rename counts as new work. It keeps no prior result. The reviewer covers each required file with one verdict under engine `file-v1`. Unit ids stay stable, with full body digests and named exclusions. Two paths sharing one id fail the pass, with both paths named. Deleted files read from the base. Other files read from the head. Files with no readable text stay required with a named access limit. Existing backlog paths stay out of the required set, each shown in the manifest with its reason. Fixed-string search at the head stops at 200 hits per term and marks the term `too_common`. Adjacent-test names mark uncertain context. Both add no required file and close none. One pass reads at most 400 required files. Batches hold at most 40 files in path order. Batches measure the full rendered prompt against 180 KB. A file that fits in no batch stays open with `input_exceeds_budget`. Files past the pass budget carry `review_budget_reached`. A halted pass records state `incomplete` with its halt word and stop counts. The claim names the open paths. A re-drive at the same base, head and engine resumes them. A changed base, head or engine retires every prior result. The reviewer prompt numbers every file it reads, with hints and excluded paths beside it. The findings schema adds `coverage`, `examined_scope` and `known_limits`. One entry per numbered file names its verdict, finding links, evidence and reason. The scope note stays even when nothing was found. `validate.Review` reads the answer with the numbered batch. Each unit number shows once. Finding numbers name returned findings. Evidence names a supplied path and revision. Spans sit inside the supplied text. Bad shape exits 1. Bad coverage exits 2, naming the missing, duplicate and unknown numbers for the retry. The review leg lists the required set before the first model call. It posts an opening generation with every unit outstanding. It then reads one batch at a time. It posts one full generation per accepted batch. A batch answer that leaves out a unit is asked once more with the missing numbers named. The second miss ends the leg and posts nothing. After a resolve pushes, the next review reads the repair delta first. It then reads the full scope after it. The pass writes the repair pair only after it reads every current file. Findings hold a line, file or outside-diff anchor. The leg posts a file-level comment for a changed file with no hunk line. A finding off the changed files keeps its id with a top-level comment and reply. Every green report passes one convergence rule. A pass needs no open fixable finding and a current ledger. Required and covered counts match. No file stays open or unexamined. The scope note is present. Any repair pair is confirmed. A stale label never reports green. A stale marker never reports green. An open file never reports green. A missing scope note never reports green. An unconfirmed repair never reports green. Coverage generations publish through strict comment reads: shards first with position and digest checks, a base and head recheck, then the manifest last. Selection keeps only the trusted author's comments at the exact base, head and engine and refuses missing, altered, reordered, corrupt or unreadable state. Past 32 shards the pass keeps the last full generation and records stop totals with the limit name. The manifest names verification status `not_implemented` and five nulls: no check runs in this release, and `crossrev/converged` means review work is complete. Pass markers move to v2. New markers open with `v:2` and hold the coverage manifest id, the stop counts and the repair pair. Markers at `v:1` still read for findings and pass numbers, but they add no coverage. Readers refuse `v:3` and later. The halt word is one of three. Recorded limits use two words. The repository files move from version 1 to version 2. A file that still declares `version: 1` is refused with the current version named as the fix. Run `crossrev init --upgrade` to re-render workflows. It leaves the policy file alone, so change the version line by hand. No new setting ships with the move. `tests/test-review-intelligence.sh` drives the contract through the binary. Fixtures under `tests/fixtures/intelligence` hold the expected sets. Public docs explain coverage in plain words: required, covered and outstanding are defined on first use, and the converged rows state the loop outcome.
- **A locally built binary reports its commit.** `crossrev version` prints `X.Y.Z-<short-sha>`, with `-dirty` when the tree had uncommitted changes, for anything `scripts/install-local.sh` builds. Release builds still print plain SemVer, so the release agreement gate is untouched. `CROSSREV_VERSION_OVERRIDE` replaces the whole string when set.
- **`crossrev init` warns when the pin carries no release tag.** The workflows it writes would fail on their first run with an error about a missing release; the plan now says so beside the pin, naming the consequence. It still proceeds — testing unreleased workflow changes against a real repository is deliberate, and the testbed exists for it. It warns only when the lookup answered: when the remote cannot be reached at all, the plan says the question went unanswered instead of stating a cause it never established.

### Changed

- **The install scripts swap names and the build centralises on one script.** `bootstrap.sh` becomes `install.sh` — it downloads the release binary, which is what that filename means everywhere else — and the checkout builder moves to `scripts/install-local.sh`. `scripts/build-native.sh` becomes `scripts/build-binary.sh`, takes a target (`darwin-arm64`, `linux-amd64`, `host`), and the release workflow's two inline builds now call it, so the version-agreement gate verifies a binary produced the same way as the ones it publishes. The documented one-command install URL changes accordingly.

### Fixed

- **`crossrev init` derives the pin's tag comment from the pinned commit.** The tag used to come from `git describe` in whatever checkout sat near the binary, so one binary wrote two different comments from two locations — and the one that looked informative named the wrong commit. The lookup is now the one the composite action already performs, so both answer the same way. A commit no release tag points at writes `untagged`, which is then true; when the remote cannot be asked at all, the comment stays `untagged` but the plan says the lookup failed rather than claiming no release exists. The lookup runs under a twenty-second timeout with every prompt disabled — terminal, askpass and SSH — so a stalled connection or an SSH rewrite fails into that fallback instead of blocking init.

## [0.6.2] — 2026-09-16

### Fixed

- **`crossrev doctor` accepts `--level core|harness`.** The watchdog leg installs no harness CLI and invokes no model, so `doctor`'s hard-coded harness requirement failed it before any work. Both levels already existed in `internal/preflight` with no way for a caller or the composite action to select the lower one. Unset continues to default to `harness`.

- **The composite action asks each leg for only the preflight it needs.** The watchdog and `status` legs install and invoke no harness CLI, so the hard-coded harness preflight failed them before any work. The preflight step now maps the leg to `--level core` for `status`, `watchdog` and `auth-refresh`, and `--level harness` for model-running legs. Unrecognised legs fall back to `harness` so an omission fails closed.

- **The composite action gains an `auth-refresh` leg.** Token refresh was the last consumer of the source-checkout delivery mode, which v0.6.0 removed; giving the action an `auth-refresh` leg puts release-binary acquisition in exactly one place. The leg forwards no pull-request or loop flags and builds `crossrev auth refresh --harness <harness> --repo <owner/name>` directly.

- **The token-refresh workflow refreshes through the action instead of checking out source.** The v0.6.0 cutover removed `bin/` and `lib/`, so checking out the repository left the workflow with no `crossrev` binary to run. The workflow template now uses the SHA-pinned composite action with `leg: auth-refresh`, ensuring binary verification and download happen in one place.

- **Correction to 0.6.0.** That release said "Nothing the tool does changes." Two things did, both in the cron workflows, and neither was caught before a consuming repository ran them: the composite action's preflight asked every leg for a harness CLI the watchdog template does not install, and the token-refresh workflow still ran `crossrev` from a `bin/` directory the same release deleted. Both are fixed here, and [ADR 0021](docs/adrs/0021-cron-legs-run-through-the-composite-action.md) adds the proof standard that would have caught them.

## [0.6.1] — 2026-09-06

### Fixed

- **A staged harness credential reaches the harness again.** A leg's child environment is an allowlist read once, at the composition root, before the leg runs. `cred.Prepare` stages the restored credential into a scratch home and exports the variable that names it — `CODEX_HOME`, `GROK_HOME`, or `XDG_DATA_HOME` for opencode — but that export lands after the read, so the child was handed a list that never named the scratch home. The harness then read its own default store, found no login on a fresh runner, and called the vendor unauthenticated. What came back was a 401 naming no cause, which reads as a bad credential rather than a credential that never arrived. `cred.Staged.Apply` now puts the pair in front of the child on both legs. **This broke automated mode on a hosted runner for codex, grok and opencode.** Claude was unaffected: `CLAUDE_CODE_OAUTH_TOKEN` is a plain secret already present when the allowlist is read. Measured on the testbed under 0.6.0: seven 401s from the Responses endpoint, and the same credential authenticated the moment the variable was present before the leg was built. The Bash this replaced could not reach the fault, because its child inherited the live environment at exec time.

## [0.6.0] — 2026-09-04

### Added

- **The Bash implementation is removed, and every route runs the Go binary.** `bin/crossrev`, `lib/*.sh`, `lib/adapters/*.sh` and `tests/capture-parity.sh` are deleted. The canonical `lib/harnesses.json` and `lib/prices.json` move to `assets/`. Checkout development is `go run ./cmd/crossrev`. `tests/run.sh` builds the binary once and runs the nine remaining shell suites against it. The twenty-one shell suites the ledger maps to Go tests are deleted with it. The policy tables they carried move to `tests/fixtures/policy/`, and the generator reads them there. The Go tests that ran the shell as a live oracle now compare against the answers it had proven, frozen in place. The composite action downloads the binary first and runs `crossrev doctor` from it. `install.sh` builds and copies with no library behind it. `package.json` keeps its name and version with no entrypoint until the platform packages exist. **Nothing the tool does changes.** The CLI surface, the schemas, the markers, the labels and every printed byte are the ones the port measured.

- **The Go binary is what gets built, downloaded and installed.** The release workflow builds `darwin/arm64` on the pinned macOS runner and `linux/amd64` in the digest-pinned Go container, one build per target. It asserts the linker's ad-hoc signature on the macOS binary. It publishes both assets with an unsigned `checksums.txt` and then creates the GitHub Release. `scripts/release-targets.json` records the runner labels and image versions each run resolves to. The npm job skips until the platform packages exist ([ADR 0020](docs/adrs/0020-the-first-native-release-ships-a-reduced-scope.md)). `crossrev init` reads its 40-character pin from the build stamp. It refuses an unstamped or modified build. The composite action downloads the asset for the runner platform and checks its digest against the release's `checksums.txt`. It refuses any other runner pair by name. `bootstrap.sh` downloads, verifies and installs atomically: private directory, verify there, rename over the destination. It says the digest proves the transfer arrived intact and nothing about the publisher. `install.sh` builds from the checkout with `scripts/build-native.sh` and copies the binary. It no longer symlinks a shell entrypoint. Gate 1 is ledgered in `tests/parity-coverage.tsv`. `scripts/check-parity-coverage.sh` refuses a missing, duplicate or non-existent destination. With `--native` it refuses a black-box destination that sources `lib/*.sh`, executes `bin/crossrev`, or runs nowhere in `scripts/test-native.sh`. CI runs the native job beside the Bash suite until the cutover: Go tests, the black-box suites against one built binary, and both checker modes. Two port defects close with it. A harness write to a quarantined path now warns on the invoke path of both legs, not only at commit time. And the review leg no longer loads three guidance files whose contents nothing reads.

- **Go native parity port, phase 4: the complete command surface.** `internal/cycle`, `internal/app`, `internal/preflight`, `internal/initcmd` and `internal/cli` now carry the Go form of every command: the local-mode cycle driver with its pairing check and finish-at-the-bound path, `status` with its liveness probe and the watchdog's single retry, the GitHub App identity, permissions, RS256 JWT, loopback OAuth listener and the five `auth` commands, the `doctor` probes with the five tools they have always checked, `init` with its byte-identical embedded workflow templates, and the parser that turns every command, flag, help request, typo and environment variable into the same output and the same exit code as `bin/crossrev`. **Nothing that ships changes.** `bin/crossrev` and `lib/` remain the implementation every install route runs; `scripts/test-native.sh` builds the binary once and runs the CLI-driven shell suites against it through `CROSSREV_TEST_BIN` in `tests/harness.sh`, and the default run still selects `bin/crossrev`. Every printed line, label write, marker key, file mode and `gh` argument array is measured from the shell rather than restated, and every package test that pins one names the shell line it came from. Where the port and the shell disagreed on something no writer produces, the difference is recorded in the test rather than reproduced; where the shell was wrong, the shell was fixed first on `main` and the port followed (a key that could not sign was installed anyway, [#192](https://github.com/carlosboeing/crossrev/issues/192)).

- **Go native parity contract and Phase 0 toolchain baseline.** The eleven-surface parity contract and frozen oracle vectors are established (`tests/fixtures/parity/`), ADR 0018 records the Go 1.27.0 native architecture and binary delivery decisions ([ADR 0018](docs/adrs/0018-go-native-parity-contract.md)), and the Go package graph is established. Toolchain verification (`scripts/verify-native-toolchain.sh`) confirms Darwin arm64 and amd64 compilation, code signing, and binary reproducibility against Go 1.27.0 before review semantics or CLI behavior change.

- **Go native parity port, phase 1: the pure decision and codec packages.** `internal/core`, `internal/policy`, `internal/prstate`, `internal/diff`, `internal/config`, `internal/validate` and `internal/prompt` now carry the Go form of the domain values and their parsers, the pass numbering, halt order, redrive predicates, severity threshold and the label colours and descriptions, the marker codec with finding identity and anchors, the three diff views, the three-layer configuration merge with its four refusals and the backlog resolver, the shape-versus-semantic payload validator, and both assembled prompts. **Nothing calls any of it.** `bin/crossrev` and `lib/` remain the shipped implementation, so no command, message, marker, label, schema or prompt byte changes for anybody running CrossRev. Each package is proved against the frozen Bash oracle under `tests/fixtures/parity/` rather than against a restatement of it — Go reads those files and never writes them, and the pass, halt and redrive tables are generated from `tests/test-state.sh` and `tests/test-legs.sh` by `go run ./internal/testgen/policy`, which `scripts/lint.sh` re-checks. Where jq and yq rewrite what they print, the port reproduces the rewrite rather than the tool, up to the point where the answer stops being a property of the format and becomes a property of the build ([ADR 0019](docs/adrs/0019-the-port-reproduces-jq-and-yq-not-their-tools.md)); two marker vectors record a mismatch and fail if the port ever starts matching, so closing that gap stays a decision somebody makes. Both JSON schemas and both `SKILL.md` files are compiled in with `go:embed`, whose patterns cannot reach above their own package, so `scripts/sync-embedded-assets.sh` generates the package-local copies from the canonical `schemas/` and `skills/` and `scripts/lint.sh` fails on drift. That is the first consequence a reader will meet: in a binary the rubric ships with the orchestrator, so editing a skill needs a build, and the frozen prompt fixtures catch a rubric edit that changes prompt bytes unintentionally.

- **Go native parity port, phase 2: the effect boundary.** `internal/exec`, `internal/vcs`, `internal/sandbox`, `internal/forge` with its `gh` adapter, `internal/ui`, `internal/runlog`, `internal/cred` and `internal/harness` now carry the Go form of everything that touches the world outside the process: starting a child, running git and resolving a push target, quarantining repository-provided harness configuration, reading and writing GitHub through `gh`, the terminal output and the private run log with its redaction, credential staging, freshness and refresh, and the harness descriptor with its five adapters and their normalized token telemetry. **Nothing calls any of it.** `bin/crossrev` and `lib/` remain the shipped implementation, so no command, message, marker, label, schema, prompt byte or harness flag changes for anybody running CrossRev.

- **Go native parity port, phase 3: both review legs.** `internal/review` and `internal/resolve` now carry the Go form of a whole pass on each side: reading the base and head context, the admission decision, the claim posted before the model is asked, the single harness invocation, then publication with its reconciliation by finding id, anchoring against the full diff, the summary, the labels, and on the resolve side the replies, the thread resolutions, the backlog persistence, the commit and the push with their recovery rules. **Nothing calls any of it.** `bin/crossrev` and `lib/` remain the shipped implementation, so no command, message, marker, label, schema, prompt byte or harness flag changes for anybody running CrossRev. One package-level test drives a finished review pass into a resolve through the marker bytes rather than through a Go value handed between the two packages, because the bytes are what a real run recovers from; the review side pins its marker to `internal/review/testdata/review-pass-1.marker` and the resolve side reads that file and runs from it.

- **Twenty-nine shell behaviours the port had got wrong are reproduced.** Each was measured by running both sides rather than read off the source, and none of them changes what ships. URL escaping used `url.PathEscape`, which leaves `+ @ : & = $` bare where jq's `@uri` percent-encodes every byte outside `A-Za-z0-9-._~`, so a link to a file whose path holds one of the six pointed elsewhere. The recorded review marker omitted `effort_reported` when the harness reported no effort, where Bash assigns the key unconditionally and the marker always holds it, null when absent. The label-failure warning printed only its first sentence and dropped the half saying the failure is cosmetic locally and fatal in automated mode. The summary footnote lost a trailing space that `${gaps:+$gaps }` writes before a footnote that may be empty. And findings and resolutions travelled as `map[string]json.RawMessage`, whose keys Go's `encoding/json` sorts and jq does not, through three writers of artifacts a later pass reads back — the commit message, the backlog file and the thread replies. The ordered-object decoder written for the price table is exported as `harness.Node` rather than copied, the resolve leg carries it end to end, and jq's rule for a key declared twice — first position, last value — is pinned by test.

  Five more were found by reviewing the files no reviewer had read, and one of them was not a byte difference at all: the resolve leg never set a payload path, and the codex adapter refuses an invocation with nowhere to write one, so a native resolve leg could not have run under codex. Beside it, a `--harness` override cleared the configured effort where Bash clears only the model and the endpoint; both substitute-harness warnings printed one sentence of two, dropping the half that says a bug missed while reviewing is missed while resolving; the resolve completion marker omitted `effort_reported` where Bash assigns it unconditionally; and a declined pass added the pass and halted labels without removing the three that are mutually exclusive with halted, which matters because the loop is label-driven. Three of the twelve are the same `omitzero` defect — a marker key absent where Bash writes null — in three separate packages, and two more are the same dropped second argument to `ui_warn`. Each has a test that fails against the code as it was.

  A later sweep for those three shapes across the whole Go tree, rather than one phase's diff, found seventeen more. Nine warnings printed one sentence where `ui_warn` prints two, dropping the half that says what the failure costs: the diff-fetch failure, the comment-create failure, the label-create failure, the concurrent-push check that did not run, the unanchored-finding count, the verdict-versus-actionable count, an abandoned stale review, an invalid harness descriptor, and a resolver reporting fixes that changed no files. Seven more were not shortened but silent — a reply that could not be threaded and the thread that could not be resolved after it, an issue the backlog could not file, the repository comment read behind `max_prs_per_day`, a finding GitHub would not anchor, a rejected commit subject silently replaced with a generic one, and a sandbox restore that failed after a rejected attempt. - **The ADR 0001 credential boundary is a type in the Go tree rather than a convention** ([ADR 0001](docs/adrs/0001-cross-model-review-loop.md), `SECURITY.md`). - **A config that parses but is not a mapping no longer dies with a raw jq error** ([#143](https://github.com/carlosboeing/crossrev/issues/143)). yq maps a comment-only or a whitespace-only document to `null` and exits 0. The run always stopped, because that assertion always fails against an empty merged config, so nothing ever ran a leg on one — the cost was diagnostic, and the cause was buried under two errors that were not it. `_cfg_yaml_to_json` now returns without a message and `cfg_load` refuses outside the substitution that read it. The two backlog refusals move to `cfg_assert_backlog`, which `cfg_load` calls directly beside the four assertions already there, so `backlog.destination` and `backlog.repository.layout` are named once before anything resolves them. `gh_label_ensure` reports its outcome in `GH_LABEL_STATE` for the reason `GH_COMMIT_SHA` exists, and `init` reads that rather than capturing stdout. The three sites on paths where `set -e` does fire behaved correctly already; they no longer depend on it, which is the point — one `||` added to a caller upstream would have turned them silently into the other kind.

- **The local run lock is keyed on the clone's shared git directory** ([#132](https://github.com/carlosboeing/crossrev/issues/132)). `run_lock_acquire` built its lock path from `git rev-parse --git-dir`. Inside a linked worktree that names the tree's own private directory under `<clone>/.git/worktrees/<name>/`. Two working trees of one clone therefore computed two different locks. Neither saw the other's, so both could drive one pull request at once — the interleaving the lock exists to prevent. `run_lock_acquire` and the status liveness check that corroborates a local run against its lock now both key on `--git-common-dir`. Both resolve an absolute physical path with `cd … && pwd -P` rather than using the value as git answers it. From a subdirectory of the main checkout git answers `../.git`, relative to the current directory; used as-is it would break the concatenated path. On macOS a logical `pwd` keeps `/var/…` where git has already answered `/private/var/…`; that would split the two trees' paths again. Automated mode is unaffected: the function returns before any of this, and GitHub's per-pull-request concurrency group is the guard there.

- **A credential shape in a model's own output no longer reaches the pull request in the clear** ([#116](https://github.com/carlosboeing/crossrev/issues/116)). The redaction covered two of the three routes out of a run: `log_redact_file` filtered the transcript kept on disk and `log_redact_str` filtered the harness error message. On a successful leg the findings text is parsed from the raw capture and published verbatim, so a reviewer quoting a configuration file, a fixture or a `.env` example put the matched string straight into an inline review comment and into the pass marker. The exposure is not a GitHub token — the harness process is started without one (ADR 0001) — but the harness's own vendor key shape, or anything else matching `sk-ant-`, `github_pat_`, `gh[pousr]_`, `xai-` or `sk-`. Every body the orchestrator writes to GitHub now passes `log_redact_publish` at the publish call: comments, comment edits, inline review comments, thread replies, a filed issue's title and body, and an issue comment. The filter sits at the publish boundary rather than at the parse, so a leg's payload is identical whether or not a run directory exists; a masked body carries a line saying a string was masked, because `sk-ant-api03-…[redacted]` with nothing around it reads as a CrossRev defect to whoever finds it; and it is idempotent, which is what makes the fallback in `gh_review_comment_create` — a body that fails to anchor is re-posted through `gh_comment_create` — mask once and note once. The marker travels inside the comment body, so the durable record `crossrev status` reads back is masked too and still parses, validates and reads back; that round trip is pinned by test. It fails closed twice over. A filter that errors withholds the body and returns a notice in its place, which is the right body for findings text and the wrong one for a body carrying a pass marker — that comment is crossrev's record of what ran (ADR 0002), so publishing the notice instead of it would leave `crossrev status` reading `passes none yet` on a pull request that did run. A marker-carrying body the filter could not process is refused instead, at the severity the write already carries: `gh_comment_create` and `gh_comment_edit` stop the run, the same refusal they already make when the API write fails, and the four writes that degrade on purpose — a thread reply, an inline comment, a filed issue and an issue comment — warn and let the fallback their callers already handle run.

- **`cred_discard` clears the staging variable it exported, whichever harness staged** ([#112](https://github.com/carlosboeing/crossrev/issues/112)). `cred_prepare` exports whatever name the descriptor gives it — `CODEX_HOME`, `GROK_HOME` or `XDG_DATA_HOME` — and the discard unset one name written out by hand, `CODEX_HOME`. So it worked for codex and for no other harness: `GROK_HOME` stayed exported at a directory that had just been removed, and `XDG_DATA_HOME`, which is opencode's staging lever and not CrossRev's variable at all, reached everything XDG-aware the same process ran afterwards. The reachable path is an ordinary one rather than an edge case: `crossrev cycle` runs both legs in one process and wraps each with a prepare and a discard. The discard now remembers the name it exported and restores what that variable held before, or unsets it when it held nothing.

- **Finding identity and the backlog path guard now behave the same everywhere CrossRev runs.** `state_finding_id` normalised its title and `state_anchor` stripped its window with an unpinned `tr`: BSD tr folds multibyte letters under a UTF-8 locale while GNU tr works on bytes, so the title `ΣIGMA` normalised to `σigma` on macOS and to itself on Linux — measured on ubuntu 24.04 under its default locale, C.UTF-8 and en_US.UTF-8, with Turkish İ, Cyrillic Д and U+00A0 diverging the same way. A finding carrying any of these got one id from a local run and a different id from the automated run of the same pull request, so it was posted twice and threaded neither; all 67 finding titles sampled from this repository's own markers are ASCII, which is probably why it never fired here. Both functions pin `LC_ALL=C` now, the byte-oriented answer every automated-mode run already produced, so ids on existing pull requests stay valid ([#123](https://github.com/carlosboeing/crossrev/issues/123)). Separately, `cfg_assert_path_inside_repo` resolved the configured backlog path with python3's normpath and fell back to raw concatenation whenever that call failed; python3 appears in none of CrossRev's dependency lists — not preflight's core set, not docs/installation.md — so on hosts without it the fallback always fired and `backlog.repository.path: ../../etc` matched the containment pattern and was accepted, pointing the deferred-work write outside the checkout. Resolution is lexical and uses jq alone now, and fails closed: traversal is refused whether or not python3 exists, and jq being missing or failing resolves to refusal rather than to the unnormalised string ([#124](https://github.com/carlosboeing/crossrev/issues/124)). The Bash side of this is pinned by parity vectors captured under `tests/fixtures/parity/` — finding ids, anchors, the marker codec and both assembled prompts byte for byte — each fixture recording the platform, tr implementation and locale it was captured under, ready for a native port to assert against.
