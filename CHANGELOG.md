# Changelog

All notable changes to revloop. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `revloop review --pr N` — one review pass. Claims before working, posts one inline comment per finding on the line it affects, records everything in a hidden marker on its own summary comment, and hands the loop to the resolve leg by label.
- `revloop resolve --pr N` — verifies every finding whatever its severity, commits and pushes what it fixed, replies in-thread, resolves what it settled, and persists deferred defects to a sink before resolving their threads.
- `revloop cycle --pr N` — the whole loop in one process, up to `max_passes`, and what a bare `revloop --pr N` runs. A thin driver over the same legs the workflows invoke, because state lives on the pull request rather than in process memory.
- `revloop status --pr N` — position *and* interruption, naming the command that resumes a leg that died mid-flight and saying whether a re-run would resume it or abandon it as stale.
- `revloop init` — the upgrade to automated mode, behind an itemised plan naming every path, secret and label, where deferred work will go and where that answer came from, and anything it would overwrite. `--dry-run`, `--yes` and `--upgrade`.
- `revloop watchdog` — finds pull requests stuck waiting on a leg, retries once by re-firing the label, then halts and comments why. Re-applying a label GitHub already holds fires no event, so the retry removes it first.
- `lib/github.sh` — the whole GitHub boundary in one file: inline comments, threaded replies, GraphQL thread resolution, labels, issues, both dedupe tiers, the commit and the push. One file because that is what makes it stubbable.
- `lib/validate.sh` — structural checks in jq on what a harness returned. Deliberately not general JSON Schema validation, which bash cannot do.
- `lib/prompt.sh` — what each leg is given. Reproduces the skill text into the prompt rather than relying on harness discovery, because the quarantine moves the discovery paths out of the checkout.
- **Runner-aware `init`.** Which harnesses are reachable in CI is a property of the runner, so `init` refuses a pairing its runner cannot serve — naming the credential's measured lifetime and both fixes — instead of installing workflows that fail at the first API call. The generated workflows differ by runner: a hosted one installs the harness per run and receives credentials as secrets, a self-hosted one does neither.
- **`revloop-token-refresh.yml` and `revloop auth refresh`** — the single writer. Using a refresh token consumes it, so one scheduled job on its own concurrency group refreshes Codex's credential and every leg only reads. The vendor's token endpoint and client id are read out of the stored credential's own claims and its issuer's OpenID discovery document, never hardcoded: the endpoint is not where the obvious guess puts it.
- **Legs restore read-only.** A restored credential lands in a throwaway home that is discarded when the leg finishes, on the fatal paths as well as the clean one, so a harness that refreshes and writes back writes somewhere nothing reads again. A leg holding under an hour of token life stops and names both ways out rather than refreshing in flight.
- **`revloop auth login --role refresher`** — a second App per owner carrying `Secrets: write` and nothing else, through the existing manifest flow. `init` derives whether a pairing needs one and never asks; a configuration that does not need it never hears of it and no key is created. Keys are now stored per owner *and* role at `<owner>.<role>.pem`, with the pre-role `<owner>.pem` still read as the loop's.
- **`init` captures `claude setup-token`** rather than asking for a paste, redacting anything token-shaped on its way to the terminal, and records the creation date — the only moment that information exists, since the token cannot be read back. `revloop auth status` warns as the year closes.
- **`revloop auth rotate`** — guided rather than absent. GitHub has no API for generating an App key, so this opens the right page, picks the downloaded `.pem` out of `~/Downloads`, proves it authenticates as that App, and only then replaces the old one.
- `lib/adapters/agy.sh` — Antigravity as a third harness. It constrains its own output natively, so it is schema-native alongside claude and codex; the amendment that asked for it expected a fenced-JSON fallback and was wrong.
- `lib/credentials.sh` — reading a token's expiry, issuer and client id from its own claims, restoring one read-only, and the refusal threshold.
- `templates/` — the workflows, the starter policy config, and a commented example operator config.
- `scripts/lint.sh` — syntax plus `shellcheck -S warning` across everything, in one command.
- A stubbed-`gh` test suite: 390 offline assertions across thirteen files, no network, no model, no pull request. `tests/stub/codex` is a tripwire rather than a stub, because a fixture whose config failed to load reached the real billed CLI once before it existed. `tests/stub/agy` is a tripwire of a different kind: it exits non-zero if a flag follows `--print`, which is the mis-parse the real CLI answers cheerfully in prose.
- `action.yml` — a composite action manifest for the day revloop is public. Its `app-token` input has no default on purpose: `GITHUB_TOKEN` writes do not trigger workflows, so defaulting it would stall the chain after pass 1 while looking healthy.
- `bin/revloop` entrypoint with `doctor`, `version` and `help`.
- **`bootstrap.sh`** — the fetched script, so a machine with nothing gets to a working CLI in one command. It finds an existing checkout before cloning another — run from inside one, reachable by following an installed symlink back to its source, or already at the destination — then hands straight to `install.sh`, which keeps owning the requirements check, the PATH entry and the skills offer. `--dir`, `--ref`, `--repo`, `--yes`, and `--skills` / `--no-skills` passed through. Nothing in the file changes with how it arrives: `gh api` fetches it while the repository is private, and `raw.githubusercontent` will serve the same bytes to a plain `curl` when it is public.
- `install.sh` **offers the skills instead of printing a command to copy**, handing over to the `skills` CLI so that CLI asks its own questions — which harnesses, project or global, symlink or copy. `--yes` means "do not ask whether to install them", which is a narrower permission than answering three questions on someone's behalf; only the scripted path passes `--global --yes` through.

### Changed

- **The second leg is `resolve`, not `address`.** The CLI verb, the label, the leg name inside every marker, the config section, the workflow file, the schema and the skill all move together. `address` parses as a noun before it parses as a verb, and `revloop/awaiting-address` on a shipping or checkout codebase reads as a street address — a label that has to be explained has failed at the only job a label has. `resolve` also matches GitHub's own vocabulary, since this leg is the one that calls `resolveReviewThread`.
- **`revloop run` is `revloop cycle`, and a bare `revloop --pr N` runs it.** `run` says nothing; every CLI has one. A **cycle** contains **passes**, and a pass has two **legs** — three words, each meaning one thing. The parse rule is written down rather than discovered: a first argument beginning with `-` is the default cycle, anything else is a subcommand, and an unknown subcommand is an error. So `revloop reviw --pr 3` dies naming the typo instead of silently running the most expensive operation the tool offers, and bare `revloop` prints help.
- **A finding's severity splits into three fields.** `severity` is now `high` / `medium` / `low`, `category` is a closed enum of `correctness`, `security`, `performance`, `maintainability`, `testing` and `docs`, and `pre_existing` is a boolean. One field was answering three unrelated questions — how bad is it, what kind is it, and did this pull request cause it — which is why a critical pre-existing security hole and a trivial pre-existing typo used to carry the same value and neither was ever fixed. Findings render as `[High · Security] Title`, with `· pre-existing` where it applies, and the summary table gains a category column. The `title` field itself is untouched, because a finding's stable id derives from it.
- **`addresser.skip_nits_after_pass` is `resolver.fix_at`.** One threshold — `high`, `medium` or `low` — naming the lowest severity a model may change code for while nobody is watching. Everything below it is still reported, still tabled, and still replied to; it is left for a human. The default is `medium`, which matches where Cursor Bugbot and OpenAI Codex sit. The verdict follows the same threshold: a pass converges when nothing at or above `fix_at`, and not pre-existing, remains. A separate reporting threshold was deliberately not added — it would make revloop's own "this is an empty review rather than a filtered one" untrue. A value outside those three is refused when the config loads, because an unrecognised threshold otherwise ranks zero, counts nothing as actionable, and makes `fix_at: medum` look exactly like a clean review.
- **Pre-existing findings are never fixed here, whatever their severity, and that is not configurable.** It is the one guardrail worth hardcoding: a repository that lets the resolve leg fix pre-existing defects gets a pull request nobody can review.

Nothing above changes what revloop does. It changes what revloop calls things, and it gives the operator one dial where there was a hardcoded rule. Taken as one breaking change now because three of the four write into state that lives on the pull request — marker leg names, labels, and the severity words in every posted comment — so it is a find-and-replace today and a per-pull-request migration once the workflows are installed anywhere.

### Fixed

- **`revloop status` recommended the address leg after the loop had converged.** It asked whether that leg had *run*, never whether one was *owed* — and a converged review is the reason the loop stopped, so none was. Following the advice would have run a pass over an empty findings list. Both that recommendation and the per-leg line now come off the review's verdict: `converged` and `blocked` owe no address leg, and the line reads "not needed" rather than "has not run", which describes work outstanding. Found by running the loop to convergence on a real pull request rather than by reading.
- **A file sink's deferrals were written after the commit, so they were committed by nothing.** The write goes into the working tree, so on an ephemeral runner it died with the container — while its thread resolved, because `tracked` was non-empty. The per-finding loop is now two passes with the commit between them: persist everything, commit, then reply and resolve. The sink write rides in the same commit as the fixes, and persist-before-resolve still holds. Reordering also exposed a second half: the commit was guarded on `fixed_count > 0`, so a pass that deferred everything and fixed nothing skipped it entirely and lost the write anyway. That guard now fires on a file-sink write too, with a commit message that says what it is for. The issue sink was never affected — it writes to GitHub, not the tree.
- **The addresser is now told which paths are not in the checkout.** The quarantine moves `CLAUDE.md`, `AGENTS.md`, `.claude/` and their siblings out before any harness runs, but the diff still carries their changes — so the reviewer raises findings there that the addresser cannot read, verify or fix. It would write to the absent path, the restore would delete the write, and the reply would report **Fixed**. Both the prompt and `skills/pr-address/SKILL.md` now name the exact list, require `deferred` rather than `fixed`, and forbid claiming a verification that cannot be performed. Excluding those paths from review instead was considered and rejected: a second model flagging a hostile instruction-file change is the point of the loop, and only the addresser is blind — the reviewer reads the diff.
- **`revloop run` always died at the address leg.** `leg_review` takes the per-PR lock and nothing releases it — only the EXIT trap clears it — so `leg_address` in the same process found a live PID holding the lock and read it as a competing run. The lock is now re-entrant for its own process, held across both legs rather than dropped between them, because releasing mid-loop would let a second terminal start a pass halfway through this one.
- **The address leg posted no replies and resolved the threads anyway.** `state_posted_finding_ids` read the `id` out of every finding marker and discarded the `leg` the marker carries, but "already written out" means different things to the two legs: inline comments for one, replies for the other. The review leg stamps a marker on every inline comment, so the address leg found every id already present, skipped each reply as a duplicate, and resolved regardless — leaving a collaborator a resolved thread with no explanation in it. The leg is now a required argument.
- **A harness that is installed but has no adapter died on `command not found`.** `run_resolve_leg` returned as soon as the binary was on PATH, so naming `kimi` — a CLI plenty of machines have — dispatched `adapter_kimi` three steps later with nothing pointing back at the configuration that asked for it. The fallback had been taught not to *choose* such a harness; it could not help when one was named outright. Now refused up front, naming the endpoint route Kimi actually takes. `tests/stub/kimi` is a tripwire that fails loudly if the dispatch is ever reached.
- **The address leg committed revloop's own source into the pull request.** `git add -A` walks `$GITHUB_WORKSPACE`, which is where the workflows put the `.revloop-src` checkout, and git stages an embedded repository as a gitlink with a warning rather than an error. The quieter half: with `.revloop-src` always staged, `git diff --cached --quiet` was never true, so the "reported fixes but changed no files" guard could not fire at all.
- **The `/revloop review` comment trigger could never fire.** The fork check was ANDed in front of the whole job condition, and an `issue_comment` payload carries no `github.event.pull_request` — so that read was null, the comparison false, and both the `on: issue_comment` block and the comment branch were dead. The check now sits inside the `pull_request` branch. A comment cannot be fork-checked from its payload at all, so that moved into the first step of the job, before any checkout: an `issue_comment` runs in the base repository's context *with secrets*, and the next step checks out `refs/pull/N/head`. A guard that fired only once revloop was running would already have put fork code on disk beside a subscription token.
- **A write to a quarantined path is no longer discarded in silence.** The restore moves `CLAUDE.md`, `AGENTS.md`, `.claude/` and friends back over whatever sits there, which is correct — letting a pull request's own instructions survive the quarantine is what the quarantine exists to stop — but a finding "fixed" by writing to one of those was reported as fixed, landed in no commit, and left the changed-nothing guard quiet because other files had changed. The clobbered paths are now named with their consequence.
- **The refresher swallowed the vendor's reason for rejecting a refresh.** Every diagnostic inside `cred_refresh_codex` went to stdout, which is where the function's return value goes, so each one was captured into the caller's `new="$(…)"` and thrown away with it. `token_expired` and `invalid_client` need different fixes and the difference is only in that body.
- **A tracker URL was treated as a repository-relative path.** `https://linear.app/acme/team/ENG` missed the GitHub-issues arm and matched the slash arm, so deferred work was written to a directory of that name inside the checkout — relative, so the inside-the-repo guard waved it through. A URL is now read the same way a bare `Linear` is: somewhere real, nothing to write to.
- **`revloop/watchdog-retried` was never cleared**, making the watchdog's retry per-pull-request rather than per-stall. A pull request that stalled on pass 1, recovered, then stalled on pass 3 was halted on the spot for having already been retried, and someone had to remove the label by hand. A completed pass now clears it.
- **A `Tracker` field carrying a parenthetical gloss stopped meaning what it said.** Sink discovery matched the Project Map value against a bare `none`, but the convention's own example reads `none (ROADMAP.md is the single source of truth for "what's next")`. The gloss made the match fail, so the declaration fell through to the sniff and deferred findings were routed into `docs/ROADMAP.md` — a destination the repository had just declared it did not have. The gloss is now dropped before matching, which fixes glossed paths in the same move. Found by running `revloop config sink` in this repository, where the offline test passed because it asserted the bare form.
- `install.sh` printed a skills command that finds nothing: the `skills` CLI does not walk into `tools/revloop/skills/` from the repository root, and `--skill` takes one name per flag rather than a comma-separated list.
- The claude adapter never ran the CLI at all when no endpoint was configured — the default local case. An empty bash array expanded with a default yields one *empty* word, so `"${prefix[@]:-}" env … claude` ran the command named `""` and failed with "command not found" and an empty error string.
- Marker reads passed `--arg` to `gh api --jq`, which takes a bare expression: the jq program became literally `--arg`. It only ever worked by falling through to a second, correct call.
- `git ls-remote` failing was read as "nobody else pushed", so the check for a concurrent push to the branch silently did nothing on an unreachable remote. It now says the check did not run.
- Adapter stderr was discarded, so a fatal error inside an adapter — an endpoint that resolves nowhere, for instance — exited the process with nothing printed.
- The single-harness fallback could resolve a leg to `kimi`, which has no adapter behind it: Kimi is reached through the claude adapter as a named endpoint. The leg then died on `adapter_kimi: command not found` rather than on the missing harness it was actually short of. `revloop doctor` reported the same three names for the same reason.
- `revloop auth install` — runs the install half on its own, for the closed tab or the new repository a year later.
- A one-shot local listener on the redirect, so the browser lands on a real page and the terminal carries on by itself. `nc -k` keeps the socket open across connections: serving one connection and re-binding was measured losing the redirect whenever anything else connected first, because the re-bind gap returns connection-refused.
- Installation verification — `auth login` opens the install page with the account prefilled, then signs an RS256 JWT with the stored key and polls until GitHub confirms the installation. "Registered" no longer reports success for an App that can reach no repository.
- `revloop auth login` — registers a GitHub App through the [App Manifest flow](https://docs.github.com/en/apps/sharing-github-apps/registering-a-github-app-from-a-manifest), prefilling the three permissions and disabling the webhook so the form offers nothing to get wrong.
- `revloop auth status` — which Apps are configured, for which owners, and whether each private key is still mode 0600.
- `install.sh` — symlinks `bin/revloop` onto PATH and reports what's missing. Skills are left to the `skills` CLI.
- `lib/ui.sh` — the six output rules from the design, enforced by the helper signatures rather than remembered per call site. `ui_warn` and `ui_die` both require a second argument, so a warning always states its consequence and an error always states the next action.
- `lib/preflight.sh` — dependency checks that name what's missing and how to install it, normalised to one `<tool> <version>` format across seven CLIs that each report themselves differently.

### Security

- **The refresher App's private key is never an organisation secret**, and never `--visibility all`. That key can rewrite repository secrets, and org-wide visibility would hand it to every workflow in the organisation — including revloop's own review job, which checks out a pull request branch and runs a model over a diff. The whole argument for a second App is that its permission is unreachable from untrusted text.
- **Each adapter strips every credential that is not its own.** The workflow hands one process every credential the pairing might need; the agent process is the one reading attacker-controlled text, and a token it never receives is one no injection can talk it into exfiltrating. Codex's raw credential is stripped too, since by then it lives in `CODEX_HOME`.
- **The single-writer guarantee is repository-scoped, and says so.** Concurrency groups do not span repositories, so one credential belongs to one repository. `init` warns on an organisation-level copy, because the repository secret takes precedence — the repository you just set up works while every other one reading the organisation copy breaks.

### Notes

- Two claims inherited from the subscription-credentials amendment failed verification and are corrected here rather than carried forward. Codex's access token lives **10 days**, not ~12 hours — the earlier figure was time-remaining on an already-old token read as a lifetime, where `iat` to `exp` on a stored credential is exactly 864000 seconds. And `agy` **does** have `--json-schema`, so the Antigravity adapter is schema-native rather than falling back to fenced JSON.
